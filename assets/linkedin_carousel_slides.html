Problem Definition

Why Phishing Detection Is Hard

Over 3.4 billion phishing emails are dispatched daily. Modern spear-phishing campaigns bypass static rule filters while large LLMs are too slow and expensive for high-volume mail gateways.

❌ Why Regex & Rules Fail

• Attackers rotate deceptive URLs, IP links, and lookalike domains constantly.

• Obfuscated HTML formatting and encoded character entities mask malicious payloads.

• High false positive rate blocks legitimate business invoices and IT communications.

❌ Why Large LLMs Aren't Feasible

• Latency Penalty: 800ms - 2,500ms per email causes unacceptable mail server backlogs.

• Extreme Cost: $0.005 to $0.02 per call at 50,000 emails/day = $9,000+/month.

• Infrastructure Dependency: Requires dedicated GPU clusters or external API uptime.

💡 The Engineering Solution: Statistical NLP + Naive Bayes

Deploy a calibrated Multinomial Naive Bayes model powered by sublinear TF-IDF n-grams. Delivers enterprise-grade 98.2% accuracy, zero third-party API dependencies, and sub-3ms CPU inference.

Architecture & Feature Engineering

The Robust NLP Pipeline

Raw email text is notoriously noisy. The preprocessor cleans the payload while systematically preserving critical cybersecurity heuristics.

1️⃣ Text Normalization

• HTML & Entity Stripping: Unescapes hex entities and strips DOM tags.

• Semantic Tokenization: Replaces raw URLs with token_url and IP destinations with token_ip_url.

• Security Stopword Filtering: Preserves domain terms ('verify', 'urgent', 'account') while stripping filler noise.

2️⃣ TF-IDF N-Gram Vectorization

• Unigrams + Bigrams (1, 2): Captures decisive phrasing like 'account suspended', 'wire transfer', 'within 24'.

• Sublinear Scaling: Replaces term frequency with 1 + log(tf) to prevent repetitive spam tokens from skewing scores.

• 1,790+ High-Discriminative Features.
